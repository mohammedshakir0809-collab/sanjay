# Building an Image Generator with AWS Lambda & Python (Step-by-Step Guide)

This guide walks through building an AWS Lambda function in **Python** that generates an **image** file using **Pillow (PIL)**, packages it as a deployable ZIP, and deploys/tests it on AWS — using both the AWS Console and the AWS CLI.

**What you'll build:** A Lambda function that accepts a JSON request (name/message), generates a PNG image in memory, and returns it Base64-encoded.

- **Language:** Python 3.11 (or 3.12)
- **Libraries:** Pillow (PIL), boto3 (AWS SDK, built into the Lambda Python runtime), optional S3 upload
- **Packaging:** pip + a deployment ZIP (Pillow needs to be built for Lambda's Linux environment)

---

## Prerequisites

- An AWS account with permission to create Lambda functions, IAM roles, and (optionally) S3 buckets.
- Python 3.11 or 3.12 installed locally.
- `pip` installed.
- AWS CLI v2 installed and configured (`aws configure`) — optional but recommended.
- Basic familiarity with the terminal / command line.

> Note: If you prefer, every CLI step below can also be done through the AWS Console UI — the console equivalents are called out where relevant.

```
lambda-image-generator/
```

```
Pillow==10.4.0
```

## STEP 3 — Write the Lambda Handler

Create `handler.py` with the following content. This handler:

- Reads a JSON input like `{"name": "Alice", "message": "Hello!"}`
- Builds a PNG image in memory using Pillow
- Returns the image as a Base64-encoded string in the response body

```python
import json
import base64
import io
from PIL import Image, ImageDraw, ImageFont


def handler(event, context):
    print(f"Received event: {event}")

    try:
        body = json.loads(event.get("body") or "{}")
    except (json.JSONDecodeError, TypeError):
        body = {}

    name = body.get("name") or "there"
    message = body.get("message") or "This image was generated by AWS Lambda!"

    try:
        image_bytes = generate_image(name, message)
        base64_image = base64.b64encode(image_bytes).decode("utf-8")

        return {
            "statusCode": 200,
            "headers": {
                "Content-Type": "image/png",
                "Content-Disposition": 'attachment; filename="greeting.png"',
            },
            "isBase64Encoded": True,
            "body": base64_image,
        }
    except Exception as e:
        print(f"Error generating image: {e}")
        return {
            "statusCode": 500,
            "body": f"Error generating image: {str(e)}",
        }


def generate_image(name: str, message: str) -> bytes:
    width, height = 800, 400
    background_color = (255, 255, 255)
    text_color = (20, 20, 20)

    img = Image.new("RGB", (width, height), color=background_color)
    draw = ImageDraw.Draw(img)

    # Lambda's Amazon Linux image includes DejaVuSans by default under this path.
    # Fall back to the default bitmap font if it isn't found.
    try:
        title_font = ImageFont.truetype(
            "/var/lang/lib/python3.11/site-packages/PIL/fonts/DejaVuSans-Bold.ttf", 36
        )
        body_font = ImageFont.truetype(
            "/var/lang/lib/python3.11/site-packages/PIL/fonts/DejaVuSans.ttf", 20
        )
    except IOError:
        title_font = ImageFont.load_default()
        body_font = ImageFont.load_default()

    draw.text((40, 60), f"Hello, {name}!", fill=text_color, font=title_font)
    draw.text((40, 130), message, fill=text_color, font=body_font)

    buffer = io.BytesIO()
    img.save(buffer, format="PNG")
    return buffer.getvalue()
```

> **Note:** Pillow's bundled fonts aren't guaranteed to exist at that exact path on every runtime image — see the **Troubleshooting Checklist** below for a more reliable option (bundling your own `.ttf` file).

---

## STEP 4 — Build the Deployable ZIP

Pillow contains compiled C extensions, so it must be installed for Lambda's Linux/x86_64 (or arm64) environment, not just your local OS.

```bash
pip install -r requirements.txt --target ./package --platform manylinux2014_x86_64 --only-binary=:all:
cp handler.py ./package/
cd package
zip -r ../lambda-image-generator.zip .
cd ..
```

This produces the deployable ZIP at:

```
lambda-image-generator.zip
```

Verify the ZIP contains the Pillow package folder (`PIL/`) — it should be a few megabytes in size, not a few kilobytes.

> If you're deploying on an **arm64** Lambda (Graviton, cheaper per‑ms), swap the platform flag to `--platform manylinux2014_aarch64` and set `--architectures arm64` when creating the function in Step 6.

## STEP 5 — Create an IAM Execution Role

Lambda needs a role granting it permission to write logs (and S3 access, if used). Using the AWS CLI:

```bash
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Service": "lambda.amazonaws.com"},
    "Action": "sts:AssumeRole"
  }]
}
EOF

aws iam create-role \
  --role-name lambda-image-generator-role \
  --assume-role-policy-document file://trust-policy.json

aws iam attach-role-policy \
  --role-name lambda-image-generator-role \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
```

**Console alternative:** IAM → Roles → Create role → Trusted entity: AWS service → Lambda → attach policy `AWSLambdaBasicExecutionRole` → name it `lambda-image-generator-role`.

---

## STEP 6 — Create the Lambda Function

### Option A — AWS CLI

```bash
aws lambda create-function \
  --function-name image-generator \
  --runtime python3.11 \
  --role arn:aws:iam::<YOUR_ACCOUNT_ID>:role/lambda-image-generator-role \
  --handler handler.handler \
  --zip-file fileb://lambda-image-generator.zip \
  --timeout 15 \
  --memory-size 512
```

### Option B — AWS Console

1. Go to **Lambda → Create function → Author from scratch**.
2. Function name: `image-generator`. Runtime: **Python 3.11** (or 3.12).
3. Under **Change default execution role**, choose **Use an existing role** and select `lambda-image-generator-role`.
4. Click **Create function**.
5. In the **Code** tab, click **Upload from → .zip file** and upload `lambda-image-generator.zip`.
6. In **Runtime settings**, set **Handler** to `handler.handler`.
7. In **Configuration → General configuration**, bump **Memory** to at least 512 MB and **Timeout** to 15 seconds (Pillow's first cold-start can be slow).

## STEP 7 — Test the Function

### Console test

- Open the function → **Test** tab → create a new test event.
- Use this event JSON (it simulates an API Gateway request):

```json
{
  "body": "{\"name\": \"Alice\", \"message\": \"Thanks for trying Lambda + Pillow!\"}"
}
```

Click **Test**. A successful run returns a 200 status with a long Base64 string in the body — that's your image.

### CLI test

```bash
aws lambda invoke \
  --function-name image-generator \
  --payload '{"body": "{\"name\": \"Alice\", \"message\": \"Hi from Lambda\"}"}' \
  --cli-binary-format raw-in-base64-out \
  response.json

cat response.json
```

### Decode the result to an actual image file

```bash
python3 -c "
import json, base64
data = json.load(open('response.json'))
img_bytes = base64.b64decode(data['body'])
open('output.png', 'wb').write(img_bytes)
"
# output.png now opens like any normal image
```

## STEP 8 (Optional) — Expose via API Gateway

To call this Lambda over HTTP instead of the CLI/console:

1. Go to **API Gateway → Create API → HTTP API**.
2. Add an integration pointing to your `image-generator` Lambda function.
3. Create a route, e.g. `POST /generate-image`.
4. Deploy the API to a stage (e.g. `$default`).
5. Call it with curl:

```bash
curl -X POST https://<api-id>.execute-api.<region>.amazonaws.com/generate-image \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","message":"Hello from the web!"}' \
  --output greeting.png
```

## STEP 9 (Optional) — Save the Image to S3 Instead of Returning It

For larger images, returning Base64 through API Gateway (6 MB payload limit) isn't ideal. Instead, upload to S3 and return a pre-signed URL. Add this to the handler after generating `image_bytes`:

```python
import boto3
import uuid

s3 = boto3.client("s3")
key = f"generated/{uuid.uuid4()}.png"

s3.put_object(
    Bucket="your-bucket-name",
    Key=key,
    Body=image_bytes,
    ContentType="image/png",
)

presigned_url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "your-bucket-name", "Key": key},
    ExpiresIn=3600,
)
# Return presigned_url in the response body instead of the raw Base64 image.
```

> If you use S3, remember to grant the Lambda role `s3:PutObject` (and implicitly `s3:GetObject` for presigning) on that bucket.

## Troubleshooting Checklist

- **"No module named 'PIL'" errors:** dependencies weren't installed into the ZIP correctly — re-run the `pip install --target ./package` command and confirm `package/PIL/` exists before zipping.
- **Import errors about compiled extensions (`.so` files):** you installed Pillow using your local machine's OS/architecture instead of `--platform manylinux2014_x86_64` (or `aarch64`). Reinstall with `--only-binary=:all:` and the correct platform flag.
- **Handler not found:** double-check the handler string matches `filename.function_name` exactly (here, `handler.handler`).
- **Timeout errors:** raise Lambda's timeout/memory — Pillow cold starts (especially loading fonts) can take a few seconds.
- **`OSError: cannot open resource` for fonts:** the DejaVuSans path bundled with Pillow isn't guaranteed across runtime versions. The most reliable fix is to include your own `.ttf` file in the deployment ZIP (e.g. `fonts/DejaVuSans.ttf`) and load it with a relative path via `os.path.join(os.path.dirname(__file__), "fonts", "DejaVuSans.ttf")`.
- **Corrupted image when testing via curl/API Gateway:** make sure `isBase64Encoded` is set to `True` and API Gateway's binary media types include `image/png`.
- **Permission denied writing to S3:** check the IAM role's attached policies include S3 access.
